# 足球場邊記錄器 v5.11

手機場邊即時記錄足球比賽事件的單頁工具。

目前版本：**v5.11**

## v5.01 本版重點

### 快速使用指南
「這是什麼？」新增：

`📖 快速使用指南`

內容以 5 個步驟說明使用流程：

1. 賽前設定
2. 裁判吹哨就開始
3. 場邊一鍵標記事件
4. 中場 / 下半場 / 延長賽 / PK
5. 賽後摘要、儲存圖片與 CSV

另外提供「場邊小技巧」：

> 時間與事件最重要；球隊名稱、賽事名稱與場地來不及輸入時，可以稍後再補。

「快速使用指南」屬於次要入口，主畫面的操作流程維持簡潔。

## 目前主要功能

### 比賽流程
- 賽前
- 比賽中
- 中場
- 下半場
- 延長賽
- PK
- 全場

### 賽事資訊
- 賽事名稱
- 場地
- 本場名單
- 守門員
- 我方 / 對手比分

主要比賽狀態固定：

- 左：`👕 名單 / 人數`
- 右：`🧤 守門員 / 背號`

PK 也保留名單與守門員資訊，並與其他比賽狀態使用一致的賽事 / 場地資訊列。

### 場邊事件
- ⚽ 進球
- 🧤 撲救
- 🥅 射門
- 🛡️ 防守
- 黃牌
- 紅牌

事件紀錄採 Compact 兩列式資訊架構：

第一列：

`時間 → 球隊 → 球員背號`

第二列：

`事件圖示 → 事件名稱 → 比分 / 助攻`

事件管理使用單一 `•••` 按鈕，再選擇：

- 編輯事件
- 刪除事件

### 賽後整理
- 本場事件統計
- 完整事件紀錄
- 比賽摘要
- 儲存圖片
- 匯出 CSV
- 新比賽

## 重要 UX 規則

我方球隊名稱空白時仍可立即開始比賽。

裁判吹哨後優先順序為：

`立即開始計時 → 記錄事件 → 有空再補資料`

- 名單固定在左

- 「這是什麼？」Header 不強調版本。
- About 底部以低調文字顯示目前版本。

## v5.04 全場「＋ 新比賽」Safari 底部遮擋修正

### 問題
iPhone Safari 底部工具列完整展開時，`＋ 新比賽` 仍可能落在瀏覽器工具列後方。

部分新版 iOS Safari 的 `visualViewport` 並不會完整回報底部工具列實際佔用高度，
因此原本只依賴動態 gap + 既有 fallback 的安全空間仍可能不足。

### 修正方式
本版不移動整個全場頁面，也不做自動捲動。

改為：

- 加大全場頁真正存在文件流中的底部 spacer。
- iPhone 寬度越小，fallback 安全尾端越大。
- `＋ 新比賽` 增加相同的 `scroll-margin-bottom`。
- 保留 `env(safe-area-inset-bottom)`。
- 保留 Safari `visualViewport` 動態 gap。
- iOS WebKit 再增加小型文件流 fallback。

### UX 原則
進入全場時畫面不會突然往上跳。

使用者正常往下滑時：

`摘要 / 儲存圖片 / 匯出 CSV → ＋ 新比賽 → Safari 安全空間`

可以完整依序出現，`＋ 新比賽` 不再被底部工具列壓住。


## v5.05 全場「＋ 新比賽」Safari 遮擋根因修正

### 這次確認到真正原因
前幾版一直增加 `fullTimeBottomSpacer`，但實際上：

```css
.finalToolsCard {
  position: fixed;
}
```

而 `＋ 新比賽` 位於 `.finalToolsCard` 裡面。

因此即使按鈕後面增加 200～300px 的 spacer，
**fixed 工具卡仍固定貼著 Safari viewport 底部**，
spacer 根本無法把按鈕往上推。

這就是 v5.04 加大安全空間後仍然被擋住的原因。

### v5.05 修正方式
本版改為：

- 全場 `.finalToolsCard` 強制改成 `position: relative`
- 移除 `left:50%`
- 移除 `bottom`
- 移除 `translateX`
- 寬度改回正常 `100%`
- `＋ 新比賽` 同樣保持正常文件流
- spacer 放在工具卡之後，現在會真正產生可捲的安全尾端

流程變成：

`事件統計`
→ `事件紀錄`
→ `摘要 / 儲存圖片 / 匯出 CSV`
→ `＋ 新比賽`
→ `Safari 安全空間`

Safari 底部工具列會蓋在最後的安全空間，而不是蓋在「＋ 新比賽」上。

### 設計原則
- 不把全場畫面整體往上推
- 不用 fixed 新比賽按鈕
- 不用 sticky
- 不用 transform 抬高
- 不自動 scrollIntoView
- 使用者正常滑到底即可完整看到按鈕


## v5.06 全場「＋ 新比賽」Safari 再修正

### 為什麼 v5.04 / v5.05 仍可能被擋
前兩版主要處理：

- fixed 工具卡
- 文件流 spacer
- safe-area
- visualViewport bottom gap

這些可以增加「可捲動空間」，但使用者提供的實際 iPhone Safari 截圖顯示：
**在全場畫面初始可視區中，`＋ 新比賽` 本身仍位於 Safari 底部工具列覆蓋區域附近。**

也就是說，問題不能只靠「按鈕後面多留空間」處理。

### v5.06 改變修正策略
手機全場狀態直接調整賽後工具的視覺順序：

1. `＋ 新比賽`
2. `摘要 / 儲存圖片 / 匯出 CSV`

因此 `＋ 新比賽` 會實際往上移約一整列高度，
不再只期待使用者往下滑或 Safari 正確回報 toolbar 高度。

### 保留項目
- 新比賽仍是全寬 Primary CTA
- 摘要 / 儲存圖片 / CSV 仍維持三欄
- 所有按鈕觸控高度仍 >= 44px
- 最底部仍保留真實文件流 spacer
- 不使用 fixed / sticky / transform 抬高按鈕
- 不自動捲動整個全場頁


## v5.07 我方隊伍預設名稱統一

### 確認結果
v5.06 程式內的真正系統預設值仍是：

`忠義`

雖然部分手機畫面可能因瀏覽器 LocalStorage 已記住上次輸入，而顯示：

`忠義國小`

但這不代表程式本身的 fallback 預設已經是 `忠義國小`。

### v5.07 修正
本版將所有真正的我方隊伍預設 fallback 統一為：

`忠義國小`

包含：

- 初始畫面顯示
- 初始 state
- 第一次載入、尚無 LocalStorage 記錄時
- 新比賽 reset fallback
- 清除狀態後重新建立比賽的 fallback

### 記憶規則
若使用者瀏覽器已經儲存「最近使用的我方隊伍名稱」，
仍優先使用該記錄，不會強制覆蓋成 `忠義國小`。

因此行為是：

`最近使用隊名` > `忠義國小（系統預設）`


## v5.08 賽前「規定時間」與「時間紀錄」角色拆分

### UX 決策
賽前不再顯示：

`⏱ 時間紀錄 / 展開`

因為比賽尚未開始，此時：

- 比賽開始
- 比賽結束
- 半場紀錄
- 實際比賽時間

都還不存在。

### 賽前改為直接顯示
獨立顯示：

`⏱ 規定時間`

並標示：

`選填・可賽後補填`

使用者不需要先展開「時間紀錄」，就能知道本場規定時間可以設定。

賽前資訊順序變成：

1. 賽事名稱 / 場地
2. 名單 / 守門員
3. 規定時間（選填）
4. 賽前狀態 / 比分
5. 開始比賽

### 比賽開始後
「規定時間」設定會移回「時間紀錄」的完整內容中。

此時才顯示：

`⏱ 時間紀錄　[規定 XX 分]　展開`

展開後可查看：

- 比賽開始 / 結束
- 上半場 / 下半場
- 中場
- 延長賽
- 實際比賽時間
- 規定時間編輯

### 程式結構
只保留一份 `regBox`，沒有建立重複的規定時間輸入欄位。

依狀態動態移動：

- 賽前 → `preRegulationHost`
- 開賽後 → `timeRegulationHost`

因此不會產生兩份資料不同步或重複 ID 的問題。


## v5.09 「規定時間」改名為「比賽時間」

### UI/UX 決策
對一般教練、家長與場邊使用者而言：

`⏱ 比賽時間`

比：

`⏱ 規定時間`

更直覺，也更容易理解為：

> 這場比賽預計踢幾分鐘。

因此本版將使用者看得到的相關用語統一改成「比賽時間」。

### 顯示方式
賽前：

`⏱ 比賽時間`
`選填・可賽後補填`

開賽後：

`⏱ 時間紀錄　20 分鐘　展開`

展開後仍可查看或修改「比賽時間」。

摘要 / 圖片 / 分享 HTML 中，也統一使用：

`比賽時間：20 分鐘`

### 內部程式
既有內部變數名稱：

- `regulationMinutes`
- `regulationDisplayText()`
- `regulationCompactText()`

維持不變。

本版只修改 UI 文案，不改動既有資料結構與時間計算邏輯。


## v5.10 賽前欄位間距統一

### 問題
v5.09 新增「比賽時間」後，賽前資訊變多。

實際 iPhone 畫面中：

- `名單 / 守門員` 與 `比賽時間` 幾乎黏在一起。
- `隊伍 / 比分` 與 `開始比賽` 也缺少明確分隔。

雖然功能沒有問題，但視覺上容易把不同層級的資訊看成同一個區塊。

### v5.10 調整
賽前主要資訊群組改成固定垂直節奏：

1. 賽事 / 場地
2. 名單 / 守門員
3. 比賽時間
4. 賽前狀態 / 隊伍 / 比分
5. 開始比賽 / 比賽結束

一般手機群組間距：`12px`

390px 以下小螢幕：`10px`

### 設計原則
只增加「群組與群組之間」的留白。

不放大：

- 卡片本身
- 按鈕高度
- 卡片內 padding

因此畫面仍保持 Compact，但資訊層級會更清楚。


## v5.11 賽前「比賽時間」Compact 化

### 問題
v5.10 雖然已把各群組間距整理好，但「比賽時間」仍包含：

- 標題
- 提示
- 大型分鐘選單
- 大型套用按鈕
- 大型清除按鈕

對一個「選填」欄位而言視覺權重偏高。

### v5.11 未設定狀態
改成單列：

`請選擇分鐘 ▾    套用`

「清除」在尚未設定時沒有實際用途，因此不再顯示。

### 已設定狀態
例如設定 20 分鐘後，改成：

`20 分鐘    修改    清除`

不再持續顯示大型選單與兩顆大按鈕。

只有按下「修改」時，才重新展開分鐘選單。

### 重設按鈕
`↻ 重設` 仍維持低頻率 tertiary action，
但稍微提高文字與邊框對比，避免戶外或深色螢幕下幾乎看不見。

### 效益
- 比賽時間區塊高度大幅下降
- 賽前畫面更接近設定清單，而不是大型表單
- 「開始比賽」仍維持唯一強 Primary CTA
- 選填資訊不會搶過名單、守門員與開賽操作
